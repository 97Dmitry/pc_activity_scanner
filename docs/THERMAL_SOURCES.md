# Температуры и thermal-события

Приложение показывает только измерения доступных источников, с именем датчика
и устройства. Температура произвольной ACPI-зоны не называется температурой CPU.
Высокая температура и низкая частота не используются как доказательство
троттлинга. `—` означает неизвестное значение.

## Linux

- `hwmon/tempN_input`: стандартные значения ABI в тысячных долях °C. Имя
  устройства берётся из `name`, название канала — из `tempN_label`, иначе
  остаётся `tempN`. Программа не предполагает, что канал №1 означает CPU.
- `thermal_zone*/temp`: тысячные доли °C; сохраняется имя зоны из `type`.
  Зоны, уже представленные через hwmon той же canonical sysfs-ветви, повторно
  не показываются. Разные источники одного устройства автоматически не
  отождествляются без подтверждённой связи.
- Analog thermistor `tempN_type=4` может требовать перевода напряжения и калибровки
  из userspace. Такой канал остаётся неизвестным: милливольты не выдаются за °C.
- Intel `thermal_throttle/core_throttle_count` и `package_throttle_count`:
  отображается число **новых переходов** аппаратного Thermal Status за последний
  непрерывный интервал. Это не текущий флаг активности троттлинга.

Счётчики выбираются один раз на physical `(package, core)` и один раз на package,
по первому доступному логическому CPU. Значения siblings/package не складываются.
Смена выбранного counter path, сброс/переполнение, отсутствие sample и разрыв
больше 15 секунд дают неизвестную дельту. Первый sample также неизвестен.
Нулевая дельта означает отсутствие новых зарегистрированных переходов, хотя
ранее начавшееся ограничение может продолжаться. Core и package — разные домены;
их события нельзя складывать как количество независимых инцидентов.

В WSL/VM sysfs может не предоставлять CPU-датчики и thermal counters. Это
ограничение источника, а не подтверждение отсутствия нагрева или троттлинга.

## Windows

Штатный PDH `Thermal Zone Information(*)\Temperature` сообщает Kelvin;
приложение переводит их в °C и подписывает **ACPI zone** с исходным именем.
Этот источник не даёт универсальной температуры CPU. Неизвестные Windows
`Throttle Reasons` не интерпретируются как CPU thermal flags.
`Win32_TemperatureProbe` не используется: Microsoft указывает, что текущие
реализации WMI не заполняют CurrentReading.

В зависимости от ОС/firmware/прав PDH-зоны могут отсутствовать. Программа
показывает недоступность и не предлагает устанавливать драйверы или повышать
права для получения универсальной температуры CPU.

## NVIDIA на обеих платформах

Если установлен штатный `nvidia-smi`, читаются UUID, имя, `temperature.gpu` и
явные `clocks_event_reasons.sw_thermal_slowdown` /
`clocks_event_reasons.hw_thermal_slowdown`. Linux использует фиксированные
`/usr/bin/nvidia-smi` или `/usr/lib/wsl/lib/nvidia-smi`, Windows —
`SystemRoot\System32\nvidia-smi.exe`; PATH или пользовательские команды не
подставляются.

Хотя бы один явно активный thermal-флаг означает подтверждённое ограничение
по данным NVIDIA. «Не активен» показывается только при двух явно неактивных
флагах; `N/A`/неподдерживаемый флаг не превращается в false. Generic
`hw_slowdown`, частота и температура для этого решения не используются:
`hw_slowdown` также может означать power brake и смену PState.

Если расширенный запрос не поддерживается или временно не сработал, выполняется
запрос только температуры; следующий опрос снова пробует полные флаги, поэтому
временная ошибка не отключает их навсегда. `N/A` сохраняется как неизвестное.
Ни драйвер, ни утилита автоматически не устанавливаются. NVIDIA CLI не является
универсальным источником для AMD/Intel. Формат CLI может меняться между версиями;
неожиданный ответ делает источник недоступным, а не запускает догадки о полях.

## Ограничения ресурсов и свежесть

Отдельный worker собирает измерения примерно раз в пять секунд, GUI и основной
collector не ждут источников. Последний immutable снимок переносится в collector
snapshot. Совокупный результат ограничен 256 строками, чтение поля sysfs — 4096
байт, сканирование одной директории — 4096 entries. Достижение лимитов обозначается.
NVIDIA запускается без shell и elevation: stdout не больше 256 КиБ, deadline
3 секунды на запрос, остановка/превышение лимита закрывают только собственный
процесс помощника. Ошибка нового опроса не сохраняет старую температуру.

Время жизни собственного CLI привязано к сборщику средствами ОС: Linux
`PR_SET_PDEATHSIG(SIGKILL)` устанавливается перед exec с повторной проверкой PPID;
это относится к обычным непривилегированным источникам. Windows создаёт новый
безымянный, ненаследуемый job с `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` и сразу
назначает в него только собственный helper. Ошибка назначения прекращает запуск
с cleanup, а не оставляет неуправляемый источник. Закрытие процесса приложения
после назначения завершает helper даже без Rust Drop. Существующие host jobs,
приоритеты, лимиты ресурсов и наблюдаемые пользовательские процессы не меняются.

Граница Windows: стандартный spawn Rust 1.95 не предоставляет стабильного
atomic job-list attribute. Между spawn и немедленным назначением остаётся короткое
окно: аварийный выход родителя именно во время запуска может оставить ещё не
назначенный helper. Собственный CreateProcess/serializer ради этого не добавлен.
Обычная отмена проверяется сразу после назначения; GUI не ждёт join/cleanup.
Интерфейс скрывает значения старше 12 секунд как неактуальные.

Успешный snapshot не означает поддержку всех датчиков машины. Наличие датчика,
доступность отдельного показателя и готовность второй точки для дельты различаются.
Новые драйверы, MSR-доступ, настройки cooling/power и системные права не меняются.
Данные этого экрана не добавляются в SQLite; это текущая диагностика.

## Проверка

Unit tests проверяют единицы/невалидные значения, `N/A` и независимые thermal
flags, лимиты/UUID-дедупликацию, reset/gap/hotplug baseline, физическую топологию
CPU, hwmon/thermal mirrors и отказ датчика без старого значения. Нативный smoke
использует настоящий worker, command helper и доступные API; никаких нагрузочных
или разогревающих экспериментов не требуется. Реальная активация thermal flags
и Intel thermal transitions на оборудовании в этом окружении не вызывается.

Нативная проверка 2026-11-16: Windows actual worker прочитал ACPI `\_TZ.TZ01`
339 K = 65,85°C и NVIDIA RTX 3070 Ti Laptop GPU 40°C; оба явных NVIDIA thermal
флага неактивны. Четыре Windows-теста модуля прошли с обязательной доступностью
ACPI и NVIDIA через test environment flags. WSL actual worker сообщил NVIDIA
40°C и неактивные thermal flags; CPU hwmon/Intel counters в WSL отсутствуют,
что явно отражено. Шесть Linux-тестов модуля прошли, включая sysfs fixtures
для единиц/дедупликации/сбросов. Windows и Linux Clippy с `-D warnings` прошли.
Это проверка чтения доступных API, а не нагрева CPU/GPU до включения ограничений.

Lifecycle regression отдельно воспроизвёл orphan на Linux и Windows до исправления;
тест намеренно завершает собственный fixture-parent через process exit без Rust
Drop и проверяет, что его helper остановлен ОС. Fixture cleanup касается только
созданного тестом процесса с проверенной native lifetime, не host jobs/PID.
