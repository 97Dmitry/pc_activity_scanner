## Данные и архитектура

- Сбор, системные запросы, CLI и доставка уведомлений вынесены из GUI.
- PID и точный native token отделяют повторное использование PID. NetHogs
  остаётся оценкой; новый процесс ждёт целого подходящего кадра.
- История мигрирует v1/v2/v3 → v4 кодом приложения; CPU/RAM и дополнительные
  поля имеют независимое покрытие. Устройства представлены сводками периода.
- Срок хранения 24 часа по умолчанию, варианты 1/3/7 дней и лимит 512 МиБ
  сохранены. Реальная пользовательская БД вручную не менялась.
- Соединения, логические CPU, датчики и журнал уведомлений не добавляют
  постоянную историю. Журнал ограничен 100 событиями, правила — 16,
  состояния — 32768, desktop queue — 8.
- CLI ограничен 256 КиБ и deadline. Linux PDEATHSIG и Windows private Job
  проверены реальным выходом fixture-parent без Rust Drop.
- Выход GUI опрашивает остановку collector/delivery с fallback 2 секунды.

## Независимое ревью

Выявлены и исправлены два P2. Regression test сначала воспроизвёл потерю
off/on между collector ticks; revision настроек теперь сбрасывает ожидание,
сохраняя журнал. Неизменённые настройки не сбрасывают интервал.

Второй тест доказал, что активный Linux CLI не отменялся при выключении.
Теперь смена поколения отменяет его примерно за 25,6 мс, собственный child
собирается, `accepted=0`, намеренная отмена не становится ошибкой источника.
Повторный полный Linux/Windows прогоны после правок прошли.

## Границы проверки

- Не выполнена ручная приёмка нового GUI, clipboard, tray и Polkit.
- Linux проверен в WSL2, не на физическом Linux с hwmon/DRM.
- Реальный thermal throttling нагрузкой не вызывался. Intel transition counters,
  многопроцессорная топология и unsupported-датчики проверены fixtures.
- Windows не предоставляет универсальный CPU temperature/throttling источник.
  ACPI-зона не объявляется CPU; AMD/vendor-specific температуры не обещаются.
- GPU memory — отчёт WDDM с известными ограничениями провайдера; рост не
  доказывает утечку. Старые GPU-суммы/ложные нули прежних версий восстановить
  невозможно; старые данные сохранены, не пересчитаны предположительно.
- В этом WSL нет `notify-send`; системная доставка сообщает недоступность,
  in-app журнал работает. Уже принятый службой ОС запрос нельзя гарантированно
  отозвать; видимость зависит от политики рабочего стола.
- Windows private Job назначается сразу после std spawn. Сохраняется короткое
  окно аварийного выхода между spawn и assignment; собственный CreateProcess
  и отдельный quoting не добавлялись. Нормальная остановка проверена.
- Не проводились overnight/многочасовой hardware soak и many-core hardware
  приёмка. CI для текущих незакоммиченных изменений удалённо не запускался.
