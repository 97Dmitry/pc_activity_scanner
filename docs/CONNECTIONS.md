# Соединения выбранного процесса

Выберите отдельный процесс в таблице или раскрытой группе. Фоновый worker
обновляет доступные TCP/UDP endpoints IPv4/IPv6 примерно раз в две секунды.
Показываются числовые локальный адрес/порт, доступный удалённый адрес/порт
и состояние TCP. Для LISTEN удалённая сторона не определена.

Список соединений не является измерением их трафика. Байты/скорости процесса
из другого источника не распределяются по endpoints. Reverse DNS, внешние
запросы, содержимое пакетов и сохранение endpoints в SQLite не выполняются.

## Источники и границы

**Windows:** `GetExtendedTcpTable` с `TCP_TABLE_OWNER_PID_ALL` и
`GetExtendedUdpTable` с `UDP_TABLE_OWNER_PID`, отдельно для `AF_INET`/`AF_INET6`.
Строки фильтруются по выбранному PID. IPv6 scope ID сохраняется при наличии.
UDP owner-PID API предоставляет только локальную конечную точку: удалённая
сторона остаётся `—`, включая подключённые UDP-сокеты.

**Linux:** socket-inode из `/proc/PID/fd` сопоставляются с `/proc/PID/net/tcp`,
`tcp6`, `udp`, `udp6` в network namespace выбранного процесса. Набор fd читается
до и после таблиц, чтобы закрытый/reused inode не переносился другому процессу.
Один socket, разделяемый несколькими процессами через fd, может присутствовать
у каждого владельца. После закрытия fd TIME_WAIT часто не имеет владельца,
поэтому это не журнал всех прошлых TCP-состояний. Linux может предоставить
remote endpoint подключённого UDP-сокета. Procfs IPv6-таблицы не дают scope ID;
неизвестный scope не выдумывается. Сокеты из другого network namespace,
переданные процессу через fd, могут отсутствовать в его `/proc/PID/net`.

Обе платформы требуют точный native creation token и проверяют его до и после
чтения. Завершение процесса, PID reuse и недоступная идентичность очищают список.
Права `/proc/PID/fd`, защищённые процессы, отключённый IPv6 и ошибки отдельных
таблиц явно отражаются в статусе. Пустая недоступная или неполная выборка не
считается доказательством отсутствия соединений. Сбор не требует UAC/Polkit.

## Производительность и согласованность

Только один выбранный процесс имеет активный запрос. Выбор хранится в одном
перезаписываемом слоте с generation; медленный ответ предыдущего выбора
отбрасывается. Смена выбранного lifetime сразу убирает старые строки, а
повторение того же выбора на repaint не перезапускает запрос. Результат и
identity передаются одним immutable `Arc<ConnectionView>`.

Лимиты: 4096 отображаемых строк, 65536 fd на каждый из двух проходов и 8 МиБ
на таблицу. Достижение лимита показывает неполноту. Размеры/число строк Windows
буферов проверяются до разбора. Worker проверяет stop каждые 100 мс между
запросами; GUI не ждёт завершения query или потока при Drop. Данные старше
допустимого UI-интервала не должны показываться как актуальные.

## Источники документации

- [GetExtendedTcpTable](https://learn.microsoft.com/en-us/windows/win32/api/iphlpapi/nf-iphlpapi-getextendedtcptable)
- [GetExtendedUdpTable](https://learn.microsoft.com/en-us/windows/win32/api/iphlpapi/nf-iphlpapi-getextendedudptable)
- [MIB_TCP6ROW_OWNER_PID: адреса, порты и scope](https://learn.microsoft.com/en-us/windows/win32/api/tcpmib/ns-tcpmib-mib_tcp6row_owner_pid)
- [Linux proc/net/tcp](https://www.kernel.org/doc/html/latest/networking/proc_net_tcp.html)

Procfs TCP-интерфейс документирован как устаревший в пользу tcp_diag. Здесь он
выбран как простой доступный read-only источник для одного процесса; это
периодическая выборка, а не трассировка каждого открытия/закрытия соединения.

## Проверки

Unit tests: native-endian procfs IPv4/IPv6, порты, inode ownership, LISTEN/UDP,
размеры таблиц/результата, PID lifetime mismatch, смена выбора и устаревший ответ.
Нативный smoke создаёт только краткие собственные loopback TCP/UDP sockets,
проверяет реальные API/фоновые ответы и исчезновение endpoints после закрытия.
IPv6 пропускается только при явной недоступности в ОС. Внешний трафик и нагрузка
на рабочую сеть для теста не требуются. Ручная приёмка UI — отдельная проверка.

Проверка 2026-11-16: шесть Linux-тестов модуля и четыре нативных Windows-теста
прошли. На обеих ОС actual query увидел семь собственных endpoints; IPv6 был
доступен, проверены TCP4 LISTEN/ESTABLISHED, UDP4, TCP6 и UDP6. Фоновый worker
вернул выборку с той же identity, смена выбора очистила её, закрытые listener
и UDP endpoint исчезли. Linux и Windows Clippy с `-D warnings` прошли;
полный промежуточный Linux suite: 166 passed, 1 ignored.
