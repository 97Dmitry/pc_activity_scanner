# Уведомления о длительной нагрузке

Правила выключены по умолчанию. Их включают явно; доставка уведомлений рабочего
стола — отдельный переключатель. Приложение только сообщает результаты измерений:
не завершает процессы, не меняет приоритеты и не управляет ресурсами системы.

Доступны общий CPU, CPU отдельного процесса, resident/working set, рост resident
без снижения, private commit, GPU% процесса и скорости I/O чтения/записи.
CPU процесса сохраняет нормализацию по всем логическим процессорам хоста.
GPU% — максимум движков, не их сумма. Private commit не равен подкачке.
Windows Process I/O включает не только физический дисковый трафик. Правила
GPU memory намеренно отсутствуют из-за известных ограничений WDDM-счётчиков.

У каждого правила есть включение, порог, длительность и cooldown. Пороги памяти
и роста заданы в байтах, I/O — в байтах/с, CPU/GPU — в процентах. Допустимые
длительности 1–3600 секунд, cooldown 1–86400 секунд. Не больше 16 правил.
Некорректные или нечисловые пороги заменяются безопасным значением для метрики;
проценты ограничены 100. Настройки сохраняют явное выключение.

Для обычного правила оба конца каждого интервала должны быть известны и не
ниже порога. Первое наблюдение лишь устанавливает начальную точку. Одинаковый
снимок не считается повторно. Пауза, старт, пропуск, неверное время, недоступная
метрика, завершение процесса или новая native-идентичность PID разрывают ожидание.
События процессов строятся по исходным процессам, независимо от группировки,
поиска и сортировки GUI. Без точного native token жизни процесса правило этого
процесса не срабатывает.

Правило «Рост resident без снижения» отслеживает одну начальную точку: рост
должен достичь порога за непрерывный интервал не короче заданной длительности,
без снижения между измерениями. Равные соседние значения допустимы. Любое
снижение или пропуск начинает измерение заново. После события начальная память
сдвигается к текущей: плоское высокое значение не вызывает повторные события о
росте. Это измеренный рост resident, а не доказательство утечки памяти.

Cooldown считается по монотонному времени снимков, а не часам UTC. Пропуск
метрики сбрасывает накопленную длительность, сохраняя cooldown того же процесса.
Изменение правил начинает длительность заново. Глобальное выключение очищает
ожидание; журнал остаётся до выхода из приложения.

Событие содержит процесс и время его жизни, метрику, порог, последнее значение
(для роста — прирост), начало/конец UTC и измеренные секунды. Оно не утверждает,
что именно этот процесс стал причиной тормозов. Движок работает в сборщике,
без запросов ОС или обращения к GUI. Он хранит до 32768 состояний правил/времён
жизни и последние 100 событий. Переполнение явно показывается в статусе;
потерянные измерения не превращаются в подтверждённую нагрузку. Журнал событий
не сохраняется в SQLite и не увеличивает срок хранения истории ресурсов.


GUI настраивает пороги памяти в МиБ, I/O в МиБ/с. Новые события показываются
в приложении; кнопка «События» открывает журнал. Системная доставка включается
отдельно: Windows Shell balloon / существующий Linux notify-send. Ошибка или
отсутствие системной службы не отключает журнал. Очередь доставки — 8 событий;
переполнение и ошибки видны в настройках. Принятие запроса API не доказывает,
что уведомление было видно: это зависит от политики рабочего стола.

Поколение доставки отменяет старые задания при выключении/паузе, включая
быстрое off/on. Уже принятый службой ОС запрос нельзя гарантированно отозвать.
Поколение настроек также сохраняет выключение правил между двумя опросами:
после повторного включения длительность начинается заново.
