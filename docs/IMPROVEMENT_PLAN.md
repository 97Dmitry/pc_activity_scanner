# План улучшения монитора

Цель: достоверные метрики, отзывчивый интерфейс и воспроизводимая проверка
Windows/Linux без смены Rust/egui. Основание: `SPEC.md` и согласованный в чате
объём. Работа в текущем checkout; публикация и защита main впоследствии
согласованы пользователем отдельно.

## Этапы и проверка

- [x] Модель (`src/model.rs`): поиск по исходным PID/путям до группировки;
  кеш представления по снимку, фильтрам и сортировке. Регрессионные тесты поиска
  и инвалидации кеша.
- [x] Сборщики (`src/network.rs`, `src/collector.rs`): ограниченная очередь
  кадров NetHogs, однократный учёт всех кадров между опросами; восстановление
  базы сетевых счётчиков после паузы; фоновое завершение helper без блокировки
  GUI. Тесты нескольких кадров, повторного PID и завершения дочернего процесса.
- [x] Настройки (`src/settings.rs`): безопасная замена существующего файла
  через проверенный кроссплатформенный механизм; тесты повторного сохранения
  и ошибки записи без потери предыдущего файла.
- [x] Интерфейс (`src/app.rs`, `src/ui/`): отделить рисование от управления
  сборщиками; фиксированная строка состояния, компактные метрики, понятные
  состояния ожидания/паузы/пустого поиска, прокрутка настроек и таблицы.
  Проверка отрисовки в виртуальном дисплее при минимальном размере окна.
- [x] Документация и Git (`README.md`, `docs/`, `.github/`, `AGENTS.md`):
  единые инструкции сборки и реальные ограничения, схема ответственности
  модулей, точный toolchain, проверка CI и diff.

## Ограничения и риски

- Не добавлять Windows ETW/PDH, базу истории или новые функции без отдельного
  обоснования. Неподдерживаемые метрики остаются `—`.
- Не повышать права GUI; helper и его дочерние процессы должны завершаться.
- Проверять быстрые переключения NetHogs, переполнение очереди, паузу,
  PID reuse и отказ файловой системы.
- Проверки: `cargo fmt --all -- --check`,
  `cargo clippy --all-targets --locked -- -D warnings`,
  `cargo test --all-targets --locked`, `cargo build --release --locked`.
- Виртуальный Linux-дисплей не заменяет приёмку Windows и настоящего трея.

## Выполнение

План выполнен последовательно в текущем checkout. Выбран минимальный рефакторинг
внутри существующего стека; Windows ETW/PDH и постоянная история остаются
отдельными задачами.

Проверка пакета изменений от 2026-11-12:

- `cargo fmt --all -- --check` — успешно.
- `cargo clippy --all-targets --locked -- -D warnings` — успешно на Linux.
- `cargo clippy --all-targets --target x86_64-pc-windows-gnu --locked -- -D warnings`
  — успешно; это проверка Windows target, не запуск MSVC-бинарника.
- `cargo test --all-targets --locked` — 32 теста, без ошибок. Ошибки поиска,
  кеширования, временного файла, доставки кадров, смены сессии и блокировки
  выключения сначала воспроизведены регрессионными проверками.
- `cargo build --release --locked` — успешно в Debian 12 / Rust 1.95.0.
- Linux Xvfb, непривилегированный пользователь: запуск и 960×600; визуально
  проверены базовая/подробная таблица, пустой поиск, пауза и настройки.
  Скриншот: `images/monitor.png`.
- `actionlint` 1.7.12, `bash -n`, `git diff --check` — успешно.
- Независимое ревью выявило блокирующее предупреждение Windows `dead_code`;
  исправлено и проверено Windows Clippy. Других подтверждённых дефектов
  ревью не выявило.

Реальные Windows, Wayland, GPU, Polkit и системный трей требуют ручной приёмки
по `QA_CHECKLIST.md`. Эти пункты не объявлены пройденными. Удалённая сборка и
публикация выполняются CI после push в `main`; результат проверяется отдельно
для отправленного SHA. Защита main и версионные релизы описаны в
`RELEASING.md`.
